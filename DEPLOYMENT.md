# Analytico Deployment Guide

Deploy the React frontend to **Vercel**, the Flask API to **Render**, and users to **MongoDB Atlas**.

**Recommended for portfolio:** `ANALYTICS_MODE=mock` (realistic demo data, no social API approval needed).

---

## 1. MongoDB Atlas

1. Create a free account at [mongodb.com/atlas](https://www.mongodb.com/atlas).
2. Create a **free M0 cluster**.
3. **Database Access** → Add user with password.
4. **Network Access** → Add IP `0.0.0.0/0` (allows Render to connect).
5. **Connect** → Drivers → copy the connection string.
6. Replace `<password>` and set the database name:

```
mongodb+srv://<user>:<password>@<cluster>.mongodb.net/analytico?retryWrites=true&w=majority
```

---

## 2. Deploy Backend (Render)

1. Push this repo to GitHub.
2. Go to [render.com](https://render.com) → **New** → **Blueprint**.
3. Connect the `ktp-analytico` repo — Render reads `render.yaml`.
4. Set these environment variables when prompted:

| Variable | Value |
|----------|-------|
| `MONGO_URI` | Your Atlas connection string |
| `CORS_ORIGINS` | `https://YOUR-VERCEL-APP.vercel.app` (update after frontend deploy) |
| `USE_MEMORY_DB` | `false` |
| `ANALYTICS_MODE` | `mock` |
| `SECRET_KEY` | Auto-generated by Render |
| `JWT_SECRET_KEY` | Auto-generated by Render |

5. Deploy. Note your API URL, e.g. `https://analytico-api.onrender.com`.
6. Verify: `curl https://analytico-api.onrender.com/health`

---

## 3. Deploy Frontend (Vercel)

1. Go to [vercel.com](https://vercel.com) → **Add New Project**.
2. Import the same GitHub repo.
3. Set **Root Directory** to `my-app`.
4. Framework preset: **Create React App** (auto-detected).
5. Add environment variable:

| Variable | Value |
|----------|-------|
| `REACT_APP_API_URL` | `https://analytico-api.onrender.com` |

6. Deploy. Note your URL, e.g. `https://analytico.vercel.app`.

---

## 4. Connect Frontend ↔ Backend

1. In **Render**, update `CORS_ORIGINS` to your Vercel URL:

```
https://analytico.vercel.app,http://localhost:3000
```

2. Redeploy the Render service (or it may auto-redeploy on env change).
3. Test the live app: register → login → open a dashboard.

## Analytics: Mock vs Live

### Portfolio (recommended): `ANALYTICS_MODE=mock`

- All three platforms show polished demo analytics.
- No Meta/TikTok/X developer approval.
- Fully demoable in interviews.

### Optional live Instagram: `ANALYTICS_MODE=live`

Requires a **Business or Creator Instagram account** linked to a Facebook Page and a Meta developer app.

1. Create an app at [developers.facebook.com](https://developers.facebook.com).
2. Add **Instagram Graph API** product.
3. Generate a long-lived access token with `instagram_basic` and `instagram_manage_insights`.
4. Get your Instagram Business Account ID.
5. Set on Render:

```
ANALYTICS_MODE=live
INSTAGRAM_ACCESS_TOKEN=<token>
INSTAGRAM_BUSINESS_ACCOUNT_ID=<id>
```

Instagram returns live data; TikTok and X still use mock until those APIs are integrated.

## Local Development

**With MongoDB Atlas** (matches production):

```bash
cp .env.example .env
# fill MONGO_URI, set USE_MEMORY_DB=false
source venv/bin/activate && pip install -r requirements.txt && python run.py
```

**Without MongoDB** (quick local testing):

```bash
# in .env
USE_MEMORY_DB=true
```

```bash
cd my-app && npm start
```

## Troubleshooting

| Issue | Fix |
|-------|-----|
| CORS error in browser | Add your Vercel URL to `CORS_ORIGINS` on Render |
| `401` on dashboards | Log in again; JWT may have expired |
| Render cold start (~30s) | Free tier sleeps; first request wakes it |
| Mongo connection failed | Check Atlas IP allowlist and `MONGO_URI` password encoding |
| Blank page on Vercel refresh | `vercel.json` rewrites are already configured |
